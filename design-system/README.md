# Miau Design System

A small, pragmatic design system for our GNOME/GTK4 + libadwaita apps. It exists
so the *next* app is faster to build and looks like it belongs to the same family
as the last one — and so our collaboration is documented well enough to share as
a case study.

This is an **internal reference**, not a published framework. Keep it lightweight:
markdown + one tokens file, updated when something real changes. Resist the urge
to build sync pipelines until we actually have 2–3 apps proving the patterns.

First app in the family: **Easel** (photo gallery). Most examples here come from it.

## What's here

| File | What it is |
|------|-----------|
| [`tokens.json`](tokens.json) | **Source of truth** for the primitives — accent colors, spacing, radii, type, elevation, layout metrics. |
| [`tokens.css`](tokens.css) | The same tokens as GTK/CSS custom values, ready to drop into an app's `style.css`. Generated by hand from `tokens.json`; keep them in sync. |
| [`patterns.md`](patterns.md) | The component catalog — Paper, Tabs bar, Photo tile, Info panel, buttons, window chrome. What each is, its tokens, its states. |
| [`gnome-gotchas.md`](gnome-gotchas.md) | The runtime playbook — the hard-won GTK4/libadwaita/Flatpak lessons that cost real time. Read before building. |

## Design language in one paragraph

Dark-first, calm, and monospaced. Content sits on a lighter **"paper"** surface
(the easel metaphor) floating on a darker window background. Chrome is quiet and
typographic — monospace labels, pill tabs, no chrome-heavy borders. One **accent**
(a periwinkle blue) carries selection, primary actions, and focus; everything else
is neutral grey. Colors come from **libadwaita's semantic palette** so the app
follows the user's light/dark theme automatically — we only add accents on top.

## The one rule that matters most

**Build on libadwaita's named colors, don't hardcode greys.** Use
`@window_bg_color`, `@view_bg_color`, `@card_bg_color`, `@window_fg_color`, etc.,
and define only *accent* tokens yourself (`@easel_blue`, …). This is what makes an
app theme-aware and consistent for free. See `patterns.md` → "Color architecture".

## How to use it for a new app

1. Copy `tokens.css` into the new app's `style.css`; rename the `--ds-*` / accent
   names if the app wants its own accent hue, but keep the *structure*.
2. Skim `patterns.md` and reuse the components you need by name.
3. **Read `gnome-gotchas.md` before writing image/threading/Flatpak code.** It will
   save you days.
4. When you invent a genuinely new, reusable pattern, add it back here.
